## Overview

环境交互系统 (Environment Interaction System) 负责管理与执行玩家与游戏世界中可互动物件之间的所有交互行为，是"环境即武器"设计支柱的核心承载系统。

在俯视角潜行游戏中，环境物件不仅是静态场景装饰，更是玩家的潜在武器、工具和信息源。系统通过射线/盒体检测识别玩家视野范围内的可互动物件（如灭火器、汽油桶、重物、电线），验证物件是否在交互范围内（距离和朝向），并在交互触发后执行对应的游戏逻辑。

物件分为七类核心类别：武器类（砖块、钢管）、爆炸类（灭火器、汽油桶）、可破坏类（灯泡、电线）、情报类（手机、账本）、障碍类（架子、绊脚线）、机关类（电梯开关、电路闸门）、投掷类（硬币、瓶盖）。交互范围按物件类型差异化设定（0.5m-2.5m），部分物件支持远程触发（通过射击引爆）。

系统通过状态机驱动交互流程，连接玩家输入（来自玩家控制器的射线检测信号）与环境物件行为，是实现"环境即武器"核心体验的关键桥梁。

## Player Fantasy

**核心情感目标：即兴创作感与战术自由的快感**

玩家与环境交互时的核心情感体验应当是"我可以用任何东西当武器"的即兴创作快感。在紧张危险的潜行过程中，玩家扫视场景，发现一个灭火器、一个汽油桶、一根钢管——脑海中瞬间形成一个"如果我这么做，就能创造奇迹"的战术计划。这种瞬间的创意构思和实现带来的满足感，是环境交互系统最重要的情感交付。

**体验层次**：

- **发现层**：场景中的每一个物件都在"呼唤"被使用。灭火器在角落等待成为爆炸物，悬挂的灯泡等待被打破制造混乱，架子上的重物等待被推倒砸向敌人。玩家不是在"寻找预设的解决方案"，而是在"发现无限的可能性组合"。

- **实现层**：当玩家决定使用某个物件时，执行应当流畅且有冲击力。灭火器爆炸时的视觉冲击、被砸碎的玻璃窗的音效反馈、汽油桶引爆后敌人被炸飞的物理反馈——这些都必须是"戏剧性的"，而非平淡的。

- **升华层**：成功的环境处决带来"我太聪明了"的自我庆祝。玩家在紧张中构思、在谨慎中执行、在混乱中收获，这种"创意执行"的循环是环境交互系统的核心情感驱动力。

**参考对标**：
- 《半条命2》的物理交互——每一个桶、每一个箱子都可以被拾取、投掷、堆叠，即兴创造自己的道路
- 《黑暗之魂》的环境杀——从高处推下巨石砸死敌人，那种"我发现了一个秘密"的惊喜感
- 《潜龙谍影5》的纸箱——看似荒谬的道具在正确使用时带来巨大的创意满足感

玩家在操作环境物件时，感受到的不应是"我按对了键"，而应是"我有无限的可能"。

## Detailed Design

### Core Rules

**1. 物件分类与属性**

每种可交互物件都属于以下七个核心类别之一：

| 类别 | 示例物件 | 交互后行为 | 远程可触发 |
|------|----------|------------|------------|
| 武器类 | 砖块、钢管、玻璃瓶 | 装备到副武器槽，作为近战武器 | 否 |
| 爆炸类 | 灭火器、汽油桶、丙烷罐 | 进入"待命"状态，长按放置，左键引爆 | 是 |
| 可破坏类 | 灯泡、电线、玻璃窗 | 触发后破坏，产生声响/改变照明 | 是 |
| 情报类 | 手机、账本、文件 | 标记任务完成，播放收集音效 | 否 |
| 障碍类 | 架子、箱子、堆叠物 | 推倒后阻挡/减速 NPC | 否 |
| 机关类 | 电梯开关、电路闸门、洒水系统 | 触发后改变场景状态（解锁捷径、改变地形） | 否 |
| 投掷类 | 硬币、瓶盖、小石子 | 进入"待命"状态，左键投掷作为诱饵 | 否 |

**2. 交互触发条件**

玩家与环境物件交互需满足以下全部条件：
- 物件在交互范围内（距离 + 朝向，根据物件类型变化）
- 物件当前处于"可用"状态（非冷却中、非已被使用）
- 玩家当前状态允许交互（非死亡、非处决动画中、非动作锁定状态）

**ObjectCategory 枚举定义**：

| 枚举值 | 说明 | 示例物件 |
|--------|------|---------|
| `WEAPON` | 武器类 | 砖块、钢管、玻璃瓶 |
| `EXPLOSIVE` | 爆炸类 | 灭火器、汽油桶、丙烷罐 |
| `DESTRUCTIBLE` | 可破坏类 | 灯泡、电线、玻璃窗 |
| `INTEL` | 情报类 | 手机、账本、文件 |
| `OBSTACLE` | 障碍类 | 架子、箱子、堆叠物 |
| `MECHANISM` | 机关类 | 电梯开关、电路闸门、洒水系统 |
| `THROWABLE` | 投掷类 | 硬币、瓶盖、小石子 |

**ObjectState 枚举定义**：

| 枚举值 | 说明 | 可转移至 |
|--------|------|----------|
| `Available` | 物件可用，可被交互 | InUse（玩家交互）、OnCooldown（远程触发） |
| `InUse` | 物件正在被使用（拾取动画、放置动画等） | OnCooldown、Depleted |
| `OnCooldown` | 物件已使用但可刷新（如投掷物被捡回、障碍物被重置） | Available |
| `Depleted` | 物件已耗尽，不可刷新（如被打碎的灯泡） | 无（场景重置时恢复） |

**3. 交互范围规范**

| 类别 | 交互半径 | 形状 | 前向角度 |
|------|----------|------|----------|
| 武器类 | 0.8m - 1.2m | 锥形 | 60° |
| 爆炸类 | 1.5m - 2.0m | 锥形 | 90° |
| 可破坏类 | 1.0m - 1.5m | 锥形 | 60° |
| 情报类 | 0.5m - 1.0m | 球形 | 180° |
| 障碍类 | 1.0m - 2.0m | 锥形 | 120° |
| 投掷类 | 1.5m - 2.5m | 球形 | 180° |
| 机关类 | 0.5m - 1.0m | 锥形 | 45° |

**4. 远程触发机制**

支持通过射击触发特定物件的效果：
- 物件拥有 `RemoteTriggerable: bool` 标志位
- 射击命中时，触发 `RemoteEffect`（如射击灭火器触发爆炸）
- 远程触发的效果应比近战触发更具戏剧性（高风险高回报）
- 远程触发会暴露玩家位置（除非使用消音器）

**5. 物件动画标签系统 (Object Animation Tag System)**

为实现动画模块化复用，减少必须制作的独立动画数量，物件使用以下标签体系：

**动画标签定义**：

| 标签 | 描述 | 可复用物件示例 | 动画片段数量 |
|------|------|---------------|-------------|
| `WEAPON_MELEE_SM` | 小型近战武器拾取/挥舞 | 砖块、玻璃瓶、小刀 | 3（拾取/挥舞/收起） |
| `WEAPON_MELEE_LG` | 大型近战武器拾取/挥舞 | 钢管、铁棍、铁管 | 3（拾取/挥舞/收起） |
| `EXPLOSIVE_CAN` | 罐装爆炸物交互 | 灭火器、汽油桶、丙烷罐 | 4（拾取/放置/引爆/踢滚） |
| `EXPLOSIVE_TOSS` | 投掷类爆炸物 | 手榴弹、燃烧瓶 | 3（拾取/投掷/引爆） |
| `DESTRUCT_GLASS` | 玻璃制品破坏 | 灯泡、玻璃窗、酒瓶 | 2（近战破坏/远程射击破坏） |
| `DESTRUCT_WOOD` | 木制品破坏 | 木箱、木门、架子 | 2（近战破坏/远程射击破坏） |
| `DESTRUCT_METAL` | 金属制品破坏 | 锁链、铁栅栏 | 2（近战破坏/工具破坏） |
| `THROW_SM` | 小型投掷物 | 硬币、瓶盖、小石子 | 2（拾取/投掷） |
| `THROW_LG` | 大型投掷物 | 重物、长杆 | 2（拾取/投掷） |
| `OBSTACLE_PUSH` | 可推动障碍物 | 箱子、桶、椅子 | 2（推倒/踢开） |
| `MECH_SWITCH` | 开关类机关 | 电灯开关、电路闸门 | 2（按下/拉下） |
| `MECH_LEVER` | 杠杆类机关 | 电梯开关、闸门拉杆 | 2（拉起/按下） |
| `INTEL_PICKUP` | 情报类物件拾取 | 手机、账本、文件 | 1（拾取） |

**标签复用原则**：
- 拥有相同标签的物件共享同一套动画片段
- 动画片段通过物件的 `ScaleMultiplier` 进行缩放适配
- 同一标签的多个物件可以有细微的姿态差异（如灭火器 vs 汽油桶），通过动画层叠加实现

**必须制作独特动画的物件数量限制**：
- MVP 阶段：每个标签类别最多 **3 种**独特变体
- 超出限制的物件必须使用现有标签体系复用动画

### States and Transitions

**物件状态机（唯一数据源）**

每个环境物件拥有独立的状态机。**环境交互系统是物件状态的唯一数据源（Single Source of Truth）**，其他系统（如武器系统）通过订阅 `ObjectStateChangedEvent` 来同步状态，不得自行维护独立的状态副本。

```
[Available] ──玩家交互──▶ [InUse] ──动画完成──▶ [OnCooldown]
     ▲                              │                    │
     │                         [远程触发]                  │
     │                              │                    ▼
     │                              └─────────────────▶ [Depleted]
     │                              │                    │
     │                         [ObjectDropped]             │
     │                              │                    │
     └──────────────────────────────┘                    │
     │                                                    │
     └───────────────────────（重置/刷新）─────────────────┘
```

| 状态 | 描述 | 可转移至 |
|------|------|----------|
| Available | 物件可用，可被交互 | InUse（玩家交互）、OnCooldown（远程触发） |
| InUse | 物件正在被使用（拾取动画、放置动画等） | OnCooldown、Depleted、**Available（玩家丢弃，触发 ObjectDropped）** |
| OnCooldown | 物件已使用但可刷新（如投掷物被捡回、障碍物被重置） | Available |
| Depleted | 物件已耗尽，不可刷新（如被打碎的灯泡） | 无（场景重置时恢复） |

> **玩家丢弃物件转移**：InUse → Available（ObjectDropped）用于玩家主动丢弃手持物件（如按 X 键丢弃）。触发后发送 `ObjectDropped` 事件通知武器系统。

**状态与武器系统的对应关系**：

| 环境交互系统状态 | 武器系统状态 | 说明 |
|----------------|-------------|------|
| Available | `Available` | 物件在场景中，未被拾取 |
| InUse | `Equipped` | 物件被玩家持有（武器系统使用"Equipped"作为对外接口，与本系统的"InUse"状态语义对应） |
| OnCooldown | `Holstered` 或 `Used` | 根据物件类型判断：消耗品（爆炸物引爆后）→Used，非消耗品（可重复使用）→Holstered |
| Depleted | `Depleted` | 物件被摧毁/消耗完毕 |

> **Held 状态语义澄清**：
> - 本系统的 `InUse` 状态表示物件正在被使用（拾取动画、放置动画等执行中）
> - 武器系统使用 `Equipped`/`Holstered`/`Used` 等状态管理物件的装备/使用状态
> - 两者通过 `ObjectStateChangedEvent` 事件同步：当本系统状态变为 `InUse` 时，武器系统将物件状态更新为 `Equipped`（手持武器）或根据物件类型更新为对应状态
> - 简言之：`InUse` 是"交互执行中"状态，`Equipped` 是"装备持有"状态，两者通过事件驱动进行状态映射

**玩家交互状态机**

玩家与环境交互时的状态流转：

```
[Idle] ──检测到可用物件──▶ [CanInteract] ──按下互动键──▶ [Interacting]
      ▲                             │                            │
      │                             │                     (播放动画)
      │                             │                            ▼
      │                             │                   [InteractionComplete]
      │                             │                            │
      └──────────（离开范围）────────┘                            ▼
                                                        [Holding / Using]
                                                     (投掷/爆炸物 → Holding)
                                                     (机关类 → Using)
```

| 玩家状态 | 描述 | 触发条件 |
|----------|------|----------|
| Idle | 玩家未与环境物件交互 | 默认状态 |
| CanInteract | 玩家视野中存在可用物件，物件高亮 + 显示提示 | 物件进入交互范围 |
| Interacting | 玩家按下互动键，播放交互动画 | 动画时长 0.3-0.5s |
| Holding | 持有可投掷/可放置的物件（爆炸物、投掷物） | 交互完成 |
| Using | 正在使用机关类物件 | 交互完成 |

### Interactions with Other Systems

**提供给 [玩家控制器]**：
- 接收玩家控制器的射线/盒体检测结果（检测到的物件引用）
- 返回物件是否在交互范围内（距离 + 朝向验证）

**提供给 [NPC AI系统]**：
- 环境物件被触发时（如爆炸、破坏），向世界广播 `EnvironmentalEvent`
- NPC AI 根据事件类型和参数决定响应行为（震惊/搜索/警戒/逃跑）

**EnvironmentalEvent 数据结构**：
```csharp
EnvironmentalEvent:
    event_type: EnvEventType  // SOUND / EXPLOSION / DESTRUCTION / DISTRACTION / BLOCKING
    position: Vector3          // 事件发生位置
    radius: float             // 影响半径（米）
    duration: float           // 持续时间（秒）
    source_object_id: int      // 来源物件 ID
```

**EnvEventType 枚举值**：

| 值 | 说明 | NPC 反应 |
|----|------|---------|
| `SOUND` | 声响（如打破玻璃） | 短暂注意 |
| `EXPLOSION` | 爆炸 | 惊吓→搜索→战斗 |
| `DESTRUCTION` | 破坏 | 注意→搜索 |
| `DISTRACTION` | 诱饵（如投掷物落地） | 移动到声源 |
| `BLOCKING` | 障碍（如推倒架子） | 绕行/移除 |

**接收来自 [NPC AI系统]**：
- NPC 当前位置和朝向（用于判定物件是否在 NPC 视野内，影响某些物件的可交互性）

**提供给 [沉重处决系统 (Gritty Takedowns)]**：
- 环境物件可作为处决工具（如将敌人摔向爆炸物、推倒架子砸死敌人）
- 提供物件的位置、类型、效果参数给处决系统

**WeaponQueryRequest/Response 接口说明**：
沉重处决系统通过以下接口查询环境物件（作为武器）的数据：

| 接口 | 方向 | 负载 | 说明 |
|------|------|------|------|
| `WeaponQueryRequest` | Gritty Takedowns → 本系统 | `{weapon_id}` | 环境处决前查询物件对应的 WeaponData |
| `WeaponQueryResponse` | 本系统 → Gritty Takedowns | `{weapon_id, WeaponData}` | 返回武器数据（含 damage_type、penetration、animation_tags） |

> **接口定义所有权**：`WeaponQueryRequest`/`WeaponQueryResponse` 接口的**定义和实现归属于沉重处决系统（Gritty Takedowns）**，本系统（环境交互系统）仅负责提供物件的 WeaponData 查询响应。

**提供给 [武器系统 (Weapon System)]**：
- 环境物件被拾取/丢弃/消耗时，通知武器系统更新物件的持有状态
- 武器系统依赖本系统作为物件状态的**唯一数据源（Single Source of Truth）**

**ObjectStateChangedEvent 数据结构**（本系统 → 武器系统）：
```csharp
ObjectStateChangedEvent:
    object_id: int              // 物件唯一ID
    object_category: ObjectCategory  // 物件类别（武器类/爆炸类/投掷类等）
    new_state: ObjectState       // Available / InUse / OnCooldown / Depleted
    position: Vector3?          // 物件当前位置（可选，用于位置相关的武器查询）
```

**事件触发时机**：

| 事件 | 触发条件 | 发送到武器系统 |
|------|----------|---------------|
| `ObjectSpawned` | 物件在场景中生成并可交互 | ✅ |
| `ObjectPickedUp` | 玩家拾取物件（Available → InUse） | ✅ |
| `ObjectDropped` | 玩家丢弃物件（InUse → Available） | ✅ |
| `ObjectUsed` | 物件效果被触发（InUse → OnCooldown 或 Depleted） | ✅ |

**接收来自 [视野与监听系统]**：
- 玩家的当前视野范围和朝向（用于确定物件是否在"可发现"状态）

**接收来自 [线索与日志系统]**：
- 某些环境物件（如情报类）被交互后，需要通知线索系统更新任务进度

**发送给 [线索与日志系统] 的事件**：

当情报类物件被玩家交互时，发送以下事件：

**事件名称**：`IntelObjectInteractedEvent`

| 参数 | 类型 | 说明 |
|------|------|------|
| `object_id` | int | 情报类物件唯一ID |
| `object_type` | IntelObjectType | 情报物件子类型（手机/账本/文件） |
| `location_id` | string | 当前位置ID |
| `interaction_timestamp` | float | 交互时间戳 |

**IntelObjectType 枚举值**：

| 枚举值 | 说明 | 示例物件 |
|--------|------|---------|
| `PHONE` | 手机类情报 | 手机、PDA |
| `LEDGER` | 账本类情报 | 账本、记录本 |
| `DOCUMENT` | 文件类情报 | 文件、地图、照片 |

**事件触发时机**：
- 玩家与环境中的情报类物件（IntelObject）完成交互时触发
- 触发后立即发送 `IntelObjectInteractedEvent` 到线索系统

**射击系统回调接口（射击击中物件后通知机制）**：

射击系统击中环境物件时，通过以下接口通知本系统：

**事件名称**：`ObjectShotEvent`

| 参数 | 类型 | 说明 |
|------|------|------|
| `object_id` | int | 被击中的物件唯一ID |
| `hit_position` | Vector3 | 射击命中点世界坐标 |
| `shooter_id` | int | 射击者实体ID（玩家或NPC） |
| `damage_dealt` | float | 造成的伤害值 |

**事件触发时机**：
- 射击射线命中 `RemoteTriggerable = true` 的物件时触发
- 命中后立即发送 `ObjectShotEvent` 到环境交互系统

**Environment 系统处理"物件被击中"流程**：

```
射击系统检测命中
    │
    ├── 物件.RemoteTriggerable == true? ──否──▶ 无响应（射线穿透）
    │
    └── 是 ──▶ 发送 ObjectShotEvent(object_id, hit_position, ...)
              │
              ▼
        检查物件状态
              │
        ├── Available ──▶ 触发 RemoteEffect，状态转为 OnCooldown 或 Depleted，冷却计时器开始
        ├── OnCooldown ──▶ 触发 RemoteEffect，效果正常生效，冷却计时器不重置
        └── Depleted ──▶ 无响应
```

> **OnCooldown 远程触发说明**：当物件处于 OnCooldown 状态时，远程触发仍可触发 RemoteEffect 效果（如爆炸物可以远程引爆多次），但冷却计时器不会因远程触发而重置。这防止玩家通过反复射击来"刷新"冷却时间。

**OnCooldown 状态与远程触发行为**：

| 当前状态 | 远程触发结果 | 冷却计时器行为 |
|---------|-------------|---------------|
| `Available` | 触发 RemoteEffect，状态转为 OnCooldown 或 Depleted | 冷却计时器开始计时 |
| `OnCooldown` | **触发 RemoteEffect，效果正常生效** | **冷却计时器不重置，继续计时** |
| `Depleted` | 无响应（射线穿透） | 不适用 |

> **设计说明**：OnCooldown 状态下远程触发仍可触发效果，这是因为爆炸物可以远程引爆多次（引爆后进入 Depleted）。冷却计时器不重置是为了防止玩家通过反复射击同一个在冷却中的物件来"刷新"冷却时间。

**爆炸类物件的 Placed 与 Detonated 状态区分**：

爆炸类物件（灭火器、汽油桶、丙烷罐）具有独特的状态子类型，作为 **OnCooldown 的子状态**存在：

| 状态（子状态） | 描述 | 在主状态机中的位置 | 冷却计时器 |
|--------------|------|------------------|-----------|
| `Available` | 物件在场景中等待被拾取/使用 | 主状态 | 未开始 |
| `InUse` | 玩家持有中（拾取动画、放置动画执行中） | 主状态 | 未开始 |
| `Placed`（OnCooldown 子状态） | 玩家放置完成，等待引爆 | OnCooldown 的子状态 | **不开始计时** |
| `Detonated`（OnCooldown 子状态） | 爆炸已触发，冷却计时开始 | OnCooldown 的子状态 | **从此刻开始计时** |
| `Depleted` | 爆炸后物件耗尽，不可再使用 | 主状态 | 不适用 |

```
[Placed] ──玩家引爆──▶ [Detonated] ──冷却完成──▶ [Available]
                                │
                                └──▶ [Depleted]（如果是一次性消耗品）
```

> **冷却起点规则**：爆炸类物件的冷却时长从 Detonated（引爆）开始计算。Placed 状态仅表示物件已放置但尚未引爆，不触发冷却计时。这确保玩家可以先放置多个爆炸物，再依次引爆，而不会出现"放置第一个后开始冷却，导致后续放置的爆炸物还没引爆就进入冷却"的违反直觉的情况。
>
> **主状态机中的位置**：Placed 和 Detonated 是 OnCooldown 的子状态，不影响主状态机的转移规则。它们仅用于爆炸类物件的冷却计时管理。

---

**OnCooldown 状态与 Weapon 系统 Equipped 状态的映射细节**：

| Environment 系统状态 | Weapon 系统对应状态 | 说明 |
|-------------------|-------------------|------|
| Available（可用） | `Available` | 物件在场景中，未被拾取，可交互 |
| InUse（使用中） | `Equipped` | 物件被玩家持有（手持武器状态） |
| OnCooldown（冷却中） | `Holstered`（非消耗品）或 `Used`（消耗品） | 物件已使用但可刷新；消耗品（爆炸物引爆后）→Used；非消耗品（障碍物重置）→Holstered |
| Depleted（耗尽） | `Depleted` | 物件被摧毁/消耗完毕 |

> **状态映射原则**：本系统（Environment）是物件状态的**唯一数据源（Single Source of Truth）**，Weapon 系统通过订阅 `ObjectStateChangedEvent` 同步状态。当物件从 Available→InUse 时，Weapon 系统更新为 Equipped；当物件进入 OnCooldown/Depleted 时，Weapon 系统根据物件类型更新为对应状态。

## Formulas

**1. 交互范围判定**

物件是否在可交互范围内需同时满足距离条件和朝向条件：

```
IsInRange = (DistanceToObject ≤ InteractionRadius) AND IsFacingObject
```

| 变量 | 定义 | 范围 |
|------|------|------|
| DistanceToObject | 玩家位置到物件中心的水平距离 | 0 - ∞ |
| InteractionRadius | 物件类型的交互半径（见详细设计表格） | 0.5m - 2.5m |
| IsFacingObject | 玩家面朝方向与物件方向的夹角是否在阈值内 | 0° - 120° |

**朝向判定（锥形范围）**：
```
IsFacingObject = AngleToObject ≤ FieldOfView / 2
AngleToObject = acos(DotProduct(PlayerFacing, DirectionToObject))
```
- PlayerFacing：玩家当前面朝单位向量
- DirectionToObject：玩家到物件的单位方向向量
- FieldOfView：物件的前向角度阈值（球形物件此值为 180°）

**示例计算**：
- 玩家位于 (5, 3)，物件位于 (6, 4)
- DirectionToObject = Normalize((1, 1)) ≈ (0.707, 0.707)
- DistanceToObject = √(1² + 1²) ≈ 1.41m
- 假设物件为武器类（半径1.0m，FOV 60°）：1.41m > 1.0m → 不可交互
- 假设物件为投掷类（半径2.5m，FOV 180°）：1.41m ≤ 2.5m AND 180°/2=90° → 在范围内

---

**2. 物件冷却时间**

物件使用后进入冷却状态，冷却完成后恢复可用：

```
RemainingCooldown = Max(0, CooldownDuration - TimeSinceUsed)
IsAvailable = (CurrentState == Available) OR (RemainingCooldown == 0)
```

| 变量 | 定义 | 典型值 |
|------|------|--------|
| CooldownDuration | 物件类型的冷却时间 | 投掷物: 5s, 障碍物: 10s, 爆炸物: 0s |
| TimeSinceUsed | 距上次使用经过的时间 | 0 - ∞ |
| CurrentState | 物件当前状态 | Available/InUse/OnCooldown/Depleted |

---

**3. 远程触发检测（射击）**

射击射线与环境物件的碰撞检测：

```
IsHit = (RaycastHit == Object) AND (Object.RemoteTriggerable == true)
TriggerEffect = Object.RemoteEffect
```

射击检测由射击系统负责，本系统提供物件的碰撞体积和 `RemoteTriggerable` 标志位。

---

**4. 环境事件生成**

物件被触发时生成环境事件，传递给 NPC AI 系统：

```
EventRadius = BaseRadius * Object.ScaleMultiplier * DistanceFalloff
EventType = DetermineEventType(Object.Category, TriggerMethod)
```

| 变量 | 定义 | 典型值 |
|------|------|--------|
| BaseRadius | 物件类型的基准影响半径 | 爆炸类: 8m, 可破坏类: 5m, 投掷物落点: 3m |
| ScaleMultiplier | 物件规模的倍数，计算公式：`ScaleMultiplier = ObjectScale / BaseScale`，其中 BaseScale 为该物件类型的设计基准尺寸 | 0.5 - 2.0 |
| **BaseScale** | 该物件类型的设计基准尺寸（用于计算 ScaleMultiplier） | 灭火器: 0.3m(高), 汽油桶: 0.5m(高), 丙烷罐: 0.4m(高), 小型砖块: 0.1m, 大型油桶: 0.6m |
| DistanceFalloff | 距离衰减系数（事件边缘效果递减），计算公式：`Clamp(1.0 - (DistanceToObject / EventRadius), 0.0, 1.0)` | 0.0 - 1.0 |
| TriggerMethod | 触发方式 | 近战触发/远程射击/连锁触发 |

> **BaseScale 参考值说明**：BaseScale 是物件类型的设计基准尺寸（高度或宽度，取主要维度）。实际物件的 ObjectScale 与 BaseScale 的比值即为 ScaleMultiplier。例如，一个 0.6m 高的汽油桶相对于 0.5m 基准的汽油桶，ScaleMultiplier = 0.6 / 0.5 = 1.2。

**事件类型映射**：

| 物件类别 | 触发方式 | 事件类型 | NPC 反应 |
|----------|----------|----------|----------|
| 可破坏类 | 近战/射击 | SoundEvent(低分贝) | 短暂注意 |
| 爆炸类 | 远程射击 | ExplosionEvent(高分贝+闪光) | 惊吓→搜索→战斗 |
| 投掷类 | 放置后引爆 | DistractionEvent | 移动到声源 |
| 障碍类 | 推倒 | BlockingEvent | 绕行/移除障碍 |

## Edge Cases

**1. 范围内多个物件的优先级判定**
- *问题*：玩家面前同时有多个物件在交互范围内，应该触发哪个？
- *处理*：优先选择距离最近的物件。显示最近物件的高亮提示，玩家可通过轻微移动摇杆切换选择目标。

**2. 物件交互时 NPC 正在看向该物件**
- *问题*：玩家尝试拾取武器，但 NPC 正在看着这个位置
- *处理*：物件仍可交互，但 NPC 会立即发现玩家动作（进入 Alert 状态）。这增加了"冒险使用"的紧张感。

**3. 玩家在动作锁定状态中尝试交互**
- *问题*：玩家处于处决动画中（Action Lock），是否能与环境物件交互？
- *处理*：否。动作锁定期间，所有环境交互输入被忽略。玩家必须等待动画完成。

**4. 连锁反应（爆炸触发其他物件）**
- *问题*：灭火器爆炸时，是否可能引爆相邻的汽油桶？
- *处理*：是。爆炸类物件拥有 `ChainTriggerable: true` 标志位和 `ChainRadius` 参数。连锁爆炸依次触发。
- **连锁延迟计算方式**：每级连锁的延迟为**固定值** `ChainExplosionDelay`（默认 0.5s），**非累积延迟**
  - 第1层（原始爆炸）：无延迟
  - 第2层（第1个被连锁的物件）：延迟 0.5s
  - 第3层（第2个被连锁的物件）：延迟 0.5s（而非 1.0s）
  - 第4层（第3个被连锁的物件）：延迟 0.5s（而非 1.5s）
- 限制最大连锁层数（建议 3 层）以控制效果和性能。

**5. 投掷物在空中时玩家受到攻击**
- *问题*：玩家刚投出诱饵，正在飞行中被敌人击中
- *处理*：投掷物保持飞行轨迹正常落地生效。玩家被击中的处理遵循 [脆弱度与伤害系统] 的规则（处决期间无无敌帧）。

**6. 物件状态在关卡重置时的恢复**
- *问题*：关卡重新加载/重置时，被使用的物件（如打碎的灯泡、消耗的投掷物）如何处理？
- *处理*：关卡重置时，所有物件状态恢复为 Available。可破坏类物件在 Depleted 状态超过 30 秒后也可自动刷新（通过关卡设计师配置）。

**7. 同时触发的多重环境事件**
- *问题*：玩家同时打破多个灯泡、触发多个爆炸
- *处理*：环境事件进入队列，依次处理（避免 NPC AI 过载）。队列最大容量 5 个，超出的事件按以下合并算法处理：
  - **同类型事件合并**：同类型事件（如多个 SOUND）在 `EventQueueMergeWindow`（默认 0.5 秒）内合并为单个事件，影响半径叠加
  - **不同类型事件排队**：不同类型事件按优先级排队，优先级低的事件等待上一事件处理完成后才处理
  - **合并判定**：`EventType` 相同 AND `SourceObjectCategory` 相同 AND 时间间隔 < `EventQueueMergeWindow` → 合并
  - **"混乱"事件**：当队列溢出时，最早的低优先级事件被替换为"混乱"事件（增加全局 NPC 混乱持续时间）

**8. 物件在玩家视野边缘被检测**
- *问题*：物件刚好在交互范围边缘，玩家无法确定是否可交互
- *处理*：在交互范围阈值内显示物件高亮；在阈值外（90%-100% 范围）显示渐变透明度，暗示"接近可交互"。

**9. 玩家死亡时持有可放置物件**
- *问题*：玩家持有爆炸物/投掷物时死亡，物件何去何从？
- *处理*：物件随玩家死亡一同消失（不保留在世界中）。这避免玩家利用死亡机制"丢弃"不需要的物件。

**10. 冷却起点规则：普通物件 vs 爆炸类物件**
- *问题*：主状态机中 OnCooldown 的冷却起点是"从物件被使用（Used）时开始计时"，但爆炸类物件的 Placed/Detonated 子状态规定冷却从 Detonated（引爆）开始计算。这是否矛盾？
- *处理*：**不矛盾，但语义不同**，具体规则如下：

| 物件类型 | "使用"定义 | 冷却起点 | 原因 |
|---------|-----------|---------|------|
| 普通物件（投掷物、障碍物等） | 玩家完成交互动作（拾取/投掷/放置） | 从交互完成那一刻开始计时 | 物件已完成其用途，进入冷却等待刷新 |
| 爆炸类物件 | 放置（Placed）但未引爆 | **从引爆（Detonated）开始计时**，放置不触发冷却 | 详见下方设计原理 |

> **爆炸类物件冷却起点设计原理**：
> - 爆炸类物件的使用流程为：拾取 → 放置（Placed）→ 引爆（Detonated）
> - 如果冷却从 Placed（放置）开始计算，会导致以下违反直觉的情况：
>   - 玩家放置第一个灭火器 → 冷却开始（15 秒）
>   - 玩家放置第二个灭火器（5 秒后）→ 第一个已进入冷却 5 秒
>   - 玩家引爆第一个灭火器时，第一个已冷却 10 秒 → 再等 5 秒即可再用
>   - 但如果此时玩家想先引爆第二个，第二个从放置起已在冷却...
> - 这会导致"先放置的物件冷却更快，后放置的物件还没引爆就要等冷却"的混乱体验
> - 从 Detonated 开始计时的语义是：**引爆意味着玩家已完成该物件的完整使用流程，冷却才正式开始**
> - 这确保玩家可以先放置多个爆炸物，再依次引爆，全部引爆后统一开始冷却

> **程序员实现提示**：
> - 普通物件的状态转移：`InUse → OnCooldown` 时立即启动 `cooldown_timer`
> - 爆炸类物件的状态转移：
>   - `InUse → Placed` 时**不启动** `cooldown_timer`，物件进入"待引爆"状态
>   - `Placed → Detonated` 时才启动 `cooldown_timer`
>   - `Detonated → Available`（冷却完成）时物件恢复可用
> - `Placed` 和 `Detonated` 是 `OnCooldown` 的子状态，不影响主状态机的转移规则，仅用于爆炸类物件的冷却计时管理

## Dependencies

**上游依赖（环境交互系统依赖谁）**：

| 系统 | 依赖类型 | 接口说明 |
|------|----------|----------|
| 玩家控制器 (Player Controller) | 硬依赖 | 接收玩家控制器的射线/盒体检测结果，提供物件是否在交互范围内的判定 |
| 视野与监听系统 (LOS & Eavesdropping) | 软依赖 | 接收玩家的当前视野范围和朝向，用于确定物件是否处于"可被发现"状态 |
| NPC AI 系统 (NPC AI System) | 软依赖 | 接收 NPC 当前位置和朝向，用于判定某些需要"避开 NPC 注视"的交互条件 |

**下游依赖（谁依赖环境交互系统）**：

| 系统 | 依赖类型 | 接口说明 |
|------|----------|----------|
| 沉重处决系统 (Gritty Takedowns) | 硬依赖 | 环境物件可作为处决工具，系统需提供物件位置、类型、效果参数 |
| 线索与日志系统 (Clue & Journal) | 软依赖 | 情报类物件被交互后通知线索系统更新任务进度 |
| NPC AI 系统 (NPC AI System) | 硬依赖 | 环境物件被触发时生成 EnvironmentalEvent，包含事件类型、位置、影响半径 |
| **武器系统 (Weapon System)** | **软依赖（订阅）** | **订阅 ObjectStateChangedEvent 同步物件状态；武器系统不自行维护物件状态副本** |
| **天气系统 (Weather System)** | **软依赖** | **环境物件状态变化可能触发天气系统事件；环境物件类型（如水体、植被）可能影响天气表现** |

> **DESTRUCT_GLASS 动画标签复用说明**：
> - 环境交互系统使用 `DESTRUCT_GLASS` 标签表示"玻璃制品被破坏"的动画（如灯泡、玻璃窗、酒瓶的破碎动画）
> - 武器系统复用了同一 `DESTRUCT_GLASS` 动画资产（破碎动画），用于可破坏物件的处决效果
> - 两者语义一致（均表示玻璃材质破碎效果），无需区分。动画系统通过物件的 `ScaleMultiplier` 进行缩放适配，以适应不同尺寸的玻璃物件

> **Weather System 下游依赖说明**：
> - 环境物件状态变化（如引爆爆炸物、大量破坏物件）可能触发天气系统的某些事件（如雷雨闪电强度增强）
> - 环境物件类型（如水体、植被密度）可能影响天气系统的视觉表现参数（如雾的浓度）

**与天气系统接口**：

环境物件状态变化可能触发天气系统事件：

| 事件类型 | 触发条件 | 数据结构 |
|---------|---------|---------|
| `EnvironmentalExplosion` | 单次爆炸达到阈值 | `EnvironmentalExplosionEvent { position: Vector3, intensity: float, object_type: string }` |
| `EnvironmentalDestruction` | 短时间内破坏 X 个物件 | `EnvironmentalDestructionEvent { count: int, time_window: float }` |

天气系统订阅这些事件，可增强雷雨闪电强度或触发特殊天气效果。事件阈值（如爆炸强度达到多少触发）由天气系统配置，本系统仅负责发送事件。

**数据流摘要**：

```
玩家控制器 ──射线检测结果──▶ 环境交互系统
                                        │
                                        ├──▶ NPC AI 系统 (EnvironmentalEvent)
                                        │
                                        ├──▶ 沉重处决系统 (物件参数)
                                        │
                                        └──▶ 线索系统 (任务更新)
```

**依赖冲突说明**：
- 玩家控制器规定"向正前方发出射线/盒体检测"，本系统严格遵循该接口
- 如未来需要支持"侧面或身后检测"，需与玩家控制器协调修改接口

> **订阅关系依赖类型说明**：
> 本文档中标注的"软依赖（订阅）"是从**事件发布者（本系统）**的角度描述的——本系统广播事件，但订阅者可以忽略。而 weapon-system.md 中标注的"硬依赖（订阅）"是从**订阅者**的角度描述的——weapon-system 必须接收这些事件才能正常工作。
> 这种视角差异是正常的，不表示文档不一致：
> - 环境交互系统 → 发布 ObjectStateChangedEvent → 软依赖（可发布）
> - 武器系统 → 订阅 ObjectStateChangedEvent → 硬依赖（必须接收）

### 调参风险提示

- `InteractionRadius_*` 设置过小 → 玩家感到"够不到"，产生挫败感
- `InteractionRadius_*` 设置过大 → 与近战武器重叠，削弱环境交互的战术意义
- `Cooldown_*` 设置过短 → 玩家可频繁使用，失去稀缺性策略
- `Cooldown_*` 设置过长 → 玩家一次性清空场景后无资源可用
- `MaxChainDepth` 设置过大 → 性能问题 + 效果过强
