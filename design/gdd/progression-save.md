# 关卡与存档系统 (Progression & Save System)

> **Status**: Approved
> **Author**: Game Designer
> **Last Updated**: 2026-04-07
> **Implements Pillar**: 致命的脆弱感 (Lethal Fragility)、罪恶的深度 (Depth of Sin)

## Overview

关卡与存档系统是《断绝：罪恶之源》的进度管理中心，负责管理玩家在各个据点的探索进度、已收集线索的持久化、以及关键NPC的生死状态。

**核心设计决策**：
- **存档时机**：仅在玩家成功撤离（Extraction）后触发自动存档
- **存档载体**：LocalStorage（MVP阶段足够，无需云同步）
- **数据粒度**：里程碑快照（Milestone Snapshot），仅保存关卡完成状态、线索ID列表、NPC生死状态，不保存瞬态数据（如玩家位置、临时状态）

本系统的设计确保玩家在"每次成功的潜行撤离"后获得进度保证，同时通过极简的数据模型降低存储开销和数据复杂度，在MVP阶段实现快速交付。

---

## Player Fantasy

玩家在存档系统中的核心情感体验应当是**"努力不白费"**与**"选择即永恒"**之间的交织。

* **撤离的安心**：当玩家经历紧张的潜行终于成功撤离时，系统自动保存进度，消除"刚才白玩了吗"的恐惧感。这种**安全感**是玩家持续投入的基石——他们知道每一次成功的行动都会被记住。

* **缺失的重量**：由于系统只保存里程碑快照，玩家一旦选择杀死某个NPC，其死亡状态将被永久记录。这意味着在读档时，NPC不会复活，线索不会重现。这种**不可逆性**强化了"罪恶的深度"支柱的情感交付——每个选择都是真正的代价。

* **拼图的延续**：已收集的线索被持久化保存，下次游戏时玩家可以从上次中断的地方继续拼凑真相。这种**连续感**让玩家感受到自己在构建一个犯罪网络的完整图谱，而非重复劳动。

**核心设计意图**：存档系统不是"进度保险箱"，而是"选择的纪念碑"。它记住玩家的成功，也记住玩家的选择，让每一个游戏回合都充满意义。

## Detailed Design

### Core Rules

**规则1：存档触发条件 (Save Trigger Conditions)**

| 触发条件 | 触发时机 | 说明 |
|---------|---------|------|
| 撤离成功 | 玩家到达撤离点并通过安全验证 | 核心存档时机 |
| 异常中断（容错） | 游戏非正常退出（如标签页关闭） | 临时存档，下次加载时询问是否恢复 |
| 手动触发（预留） | 玩家主动点击存档按钮 | MVP不实现，Vertical Slice考虑 |

**撤离成功的判定**：
1. 玩家进入撤离区域（Exit Zone）
2. 撤离区域内的敌人数量 <= 0
3. 玩家持续停留在撤离区域 >= 3秒（防止误触）
4. 同时满足以上条件后，触发自动存档

**规则2：存档数据结构 (Save Data Structure)**

```python
SaveData:
    save_version: String              # 存档格式版本，如 "1.0.0"
    timestamp: Integer                # Unix时间戳，存档创建时间
    playtime_seconds: Integer         # 累计游玩时间（秒）

    locations: Dictionary[location_id, LocationSave]
    clues: Dictionary[clue_id, ClueSave]
    npcs: Dictionary[npc_id, NPCSave]

LocationSave:
    location_id: String
    is_unlocked: Boolean              # 该关卡是否已解锁
    is_completed: Boolean             # 是否已完成（满足撤离条件）
    completion_count: Integer          # 完成次数（用于统计）

ClueSave:
    clue_id: String
    state: Enum                       # DISCOVERED / UNLOCKED / COMPLETED / MISSING
    missing_reason: String | null     # 如果是MISSING，记录原因

NPCSave:
    npc_id: String
    is_alive: Boolean                  # 生死状态
    death_timestamp: Integer | null    # 死亡时间（Unix时间戳）
```

**规则3：存档写入流程 (Save Write Flow)**

```
撤离成功触发
    │
    ▼
验证撤离条件（停留时间、安全区域）
    │
    ▼
构建SaveData快照
    │
    ▼
序列化SaveData为JSON
    │
    ▼
写入LocalStorage（键名: "severance_save_v{save_version}"）
    │
    ▼
显示"进度已保存"提示（1.5秒自动消失）
```

**规则4：存档读取流程 (Save Load Flow)**

```
游戏启动
    │
    ▼
检查LocalStorage是否存在存档
    │
    ├─── 不存在 ───▶ 进入新游戏流程，初始化空数据结构
    │
    └─── 存在 ───▶ 读取存档数据
                      │
                      ▼
                 验证存档版本
                      │
                      ├─── 版本兼容 ───▶ 解析JSON，反序列化
                      │                      │
                      │                      ▼
                      │                 校验数据结构完整性
                      │                      │
                      │                      ├─── 校验通过 ───▶ 加载游戏状态
                      │                      │
                      │                      └─── 校验失败 ───▶ 提示"存档损坏"，询问重新开始
                      │
                      └─── 版本不兼容 ───▶ 提示"存档版本过旧"，询问是否重新开始
```

**规则5：里程碑快照模型 (Milestone Snapshot Model)**

与全量快照不同，里程碑快照只记录"已完成的状态"，不记录"进行中的状态"：

| 数据类型 | 是否保存 | 理由 |
|---------|---------|------|
| 关卡完成状态 | ✅ 保存 | 里程碑数据，必须持久化 |
| 已收集线索ID列表 | ✅ 保存 | 里程碑数据，必须持久化 |
| NPC生死状态 | ✅ 保存 | 里程碑数据，必须持久化 |
| 玩家位置 | ❌ 不保存 | 瞬态数据，撤离后玩家回到起点 |
| NPC巡逻路径进度 | ❌ 不保存 | 瞬态数据，每次进入关卡重新生成 |
| 临时道具/弹药数量 | ❌ 不保存 | 瞬态数据，每关开始时重置 |
| 环境状态（门是否开启） | ❌ 不保存 | 瞬态数据，每关开始时重置 |

**规则6：版本兼容性策略 (Version Compatibility)**

- **主版本号**（1.0 → 2.0）：不兼容，需要重新开始
- **次版本号**（1.0 → 1.1）：兼容，执行数据迁移
- **补丁版本号**（1.0.0 → 1.0.1）：完全兼容，直接加载

数据迁移流程：
```
读取旧版本存档
    │
    ▼
识别缺失字段（使用默认值填充）
    │
    ▼
执行字段转换（如有格式变更）
    │
    ▼
保存为新版本格式
```

### States and Transitions

#### 存档状态机 (Save State Machine)

```
[NO_SAVE] ──新游戏──▶ [PLAYING]
    │                       │
    │                       ▼
    │                  [EXTRACTING] ◀─── 进入撤离区域
    │                       │
    │                       ▼
    │                  [SAVE_IN_PROGRESS]
    │                       │
    │                       ▼
    │                  [PLAYING] ──游戏退出──▶ [EXIT]
    │
    └───加载存档──▶ [PLAYING]
```

| 状态 | 描述 | 入口条件 | 出口条件 | 行为 |
|------|------|---------|---------|------|
| NO_SAVE | 无存档 | 首次启动或存档被删除 | 新游戏/加载存档 | 初始化空数据结构 |
| PLAYING | 正常游戏中 | 新游戏/加载存档/存档完成 | 进入撤离区域/游戏退出 | 正常游戏逻辑 |
| EXTRACTING | 撤离中 | 玩家进入撤离区域 | 撤离条件满足/离开撤离区域 | 倒计时UI显示 |
| SAVE_IN_PROGRESS | 存档中 | 撤离倒计时完成 | 存档写入完成/存档失败 | 显示保存提示 |
| EXIT | 退出游戏 | 游戏关闭 | — | 清理资源 |

#### 存档写入状态

| 状态 | 描述 |
|------|------|
| IDLE | 空闲，无存档操作 |
| WRITING | 正在写入LocalStorage |
| VERIFYING | 正在验证写入完整性 |
| SUCCESS | 写入成功 |
| FAILED | 写入失败 |
| CORRUPTED | 数据损坏 |

#### NPC生死状态机

```
[ALIVE] ──玩家攻击──▶ [DYING] ──动画完成──▶ [DEAD]
    │                                          │
    │◀─────────── 读档恢复（如果存档状态为ALIVE）◀─┘
```

| 状态 | 描述 | 可转移至 | 触发条件 |
|------|------|---------|---------|
| ALIVE | NPC存活 | DYING | 玩家对NPC造成致命伤害 |
| DYING | 死亡动画中 | DEAD | 死亡动画播放完成 |
| DEAD | 已死亡 | 无（终止态） | DYING状态结束 |

**注意**：DEAD状态的NPC在读档后保持DEAD，不会有"读档复活"的逻辑。

### Interactions with Other Systems

#### 数据流入 (Inputs)

| 来源系统 | 数据内容 | 处理方式 |
|---------|---------|---------|
| **关卡系统** | `LevelCompleted(location_id)` | 标记该关卡为完成，更新 `locations[location_id].is_completed` |
| **线索系统** | `ClueStateChanged(clue_id, new_state)` | 玩家收集/解锁线索时，更新 `clues[clue_id].state` |
| **NPC AI系统** | `NPCDeath(npc_id)` | NPC死亡时，更新 `npcs[npc_id].is_alive = false` |
| **玩家控制器** | `PlaytimeUpdated(seconds)` | 累计游玩时间，每30秒更新一次 |

#### 数据流出 (Outputs)

| 目标系统 | 发送数据 | 说明 |
|---------|---------|------|
| **关卡系统** | `LevelLoadRequest(location_id, initial_state)` | 加载关卡时，根据存档恢复关卡解锁/完成状态 |
| **线索系统** | `ClueRestoreRequest(clue_ids)` | 游戏启动时，根据存档恢复线索状态 |
| **NPC AI系统** | `NPCStateRestoreRequest(npc_states)` | 游戏启动时，根据存档恢复NPC生死状态 |
| **UI系统** | `SaveStatusQuery()` | 查询当前存档状态（用于显示存档图标） |
| **UI系统** | `SaveCompleteNotification()` | 存档完成时通知UI显示提示 |

#### 接口所有权

| 接口 | 拥有者 | 流向 |
|------|-------|------|
| `LevelCompleted` 事件 | 关卡系统 | 关卡系统 → 存档系统 |
| `ClueStateChanged` 事件 | 线索系统 | 线索系统 → 存档系统 |
| `NPCDeath` 事件 | NPC AI系统 | NPC AI系统 → 存档系统 |
| `LevelLoadRequest` 查询 | 关卡系统 | 存档系统 → 关卡系统 |
| `ClueRestoreRequest` 查询 | 线索系统 | 存档系统 → 线索系统 |
| `NPCStateRestoreRequest` 查询 | NPC AI系统 | 存档系统 → NPC AI系统 |

## Formulas

**公式1：存档键名生成**

```
SaveKey = "severance_save_v" + save_version
```

| 变量 | 类型 | 值 | 说明 |
|------|------|-----|------|
| save_version | String | "1.0.0" | 当前存档格式版本 |
| SaveKey | String | "severance_save_v1.0.0" | LocalStorage中的键名 |

---

**公式2：撤离安全判定**

```
CanExtract = (
    player_in_exit_zone == true
) AND (
    enemies_in_zone_count <= 0
) AND (
    exit_timer >= 3.0
)
```

| 变量 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| player_in_exit_zone | Boolean | false | 玩家是否在撤离区域内 |
| enemies_in_zone_count | Integer | 0 | 撤离区域内敌人数量。数据来源：关卡系统维护撤离区域的触发器，当 NPC 进入触发器时计数+1，离开时-1 |
| exit_timer | Float | 0.0 | 撤离倒计时（秒） |

**撤离成功 = 玩家在区域内 AND 区域内无敌人 AND 停留>=3秒**

**撤离倒计时行为细则**：
- 玩家进入撤离区域时，若 `enemies_in_zone_count > 0`，倒计时**不启动**
- 倒计时进行中，若敌人进入撤离区域：
  - 倒计时**暂停**（不归零，保留已累计时间）
  - 显示撤离中断警告（进度条变红闪烁）
- 敌人离开撤离区域后，倒计时**从暂停点恢复**
- 若暂停累计时间超过 `MaxExitTimerPause`（10秒），倒计时**重置为0**
- 倒计时进行中，玩家离开撤离区域 → 倒计时重置为0

---

**公式3：存档数据完整性校验**

```
IsValidSave = (
    save_version is not null
) AND (
    locations is not null
) AND (
    clues is not null
) AND (
    npcs is not null
) AND (
    locations is Dictionary
) AND (
    clues is Dictionary
) AND (
    npcs is Dictionary
)
```

| 检查项 | 失败后果 |
|--------|---------|
| save_version 缺失 | 标记为 CORRUPTED |
| locations 不是字典 | 标记为 CORRUPTED |
| clues 不是字典 | 标记为 CORRUPTED |
| npcs 不是字典 | 标记为 CORRUPTED |

---

**公式4：数据迁移版本检测**

```
NeedsMigration = (
    current_version.major != save_version.major
)

MigrationType = if (current_version.major > save_version.major):
    "major"  # 不兼容，拒绝加载
elif (current_version.major < save_version.major):
    "future"  # 存档版本比当前版本新，无法处理
elif (current_version.minor > save_version.minor):
    "minor"  # 向后兼容，使用默认值填充新字段
else:
    "patch"  # 完全兼容，直接加载
```

| 迁移类型 | 处理方式 |
|---------|---------|
| patch（补丁版本不同） | 直接加载，不做任何转换 |
| minor（次版本不同） | 使用默认值填充新字段，保持兼容性 |
| major（主版本不同） | 拒绝加载，提示用户重新开始 |

---

**公式5：存储空间估算**

```
EstimatedSaveSize = (
    1KB  # save_version, timestamp, playtime
    + locations_count * 100 bytes
    + clues_count * 150 bytes
    + npcs_count * 80 bytes
)
```

| 数据项 | 每条估算大小 | 示例 |
|--------|------------|------|
| 基本信息 | ~1KB | save_version + timestamp + playtime |
| 每个关卡 | ~100 bytes | location_id + is_unlocked + is_completed |
| 每条线索 | ~150 bytes | clue_id + state + missing_reason |
| 每个NPC | ~80 bytes | npc_id + is_alive + death_timestamp |

**MVP场景估算**：10个关卡 + 100条线索 + 50个NPC ≈ 1KB + 1KB + 15KB + 4KB ≈ **21KB**

LocalStorage单键限制通常为5MB，21KB远低于限制。

## Edge Cases

**边缘情况1：撤离过程中游戏崩溃**

*问题*：玩家在撤离倒计时（3秒）进行中时，游戏非正常退出。

*处理*：
- 游戏崩溃前的最后一次有效存档是上一个关卡的存档
- 如果是第一个关卡，则无存档，损失该关卡进度
- 建议：撤离倒计时期间不显示"保存中"，只在保存完成后才显示"进度已保存"

*风险等级*：低 — 这种情况极为罕见，且符合"撤离未成功就不存档"的设计理念

---

**边缘情况2：LocalStorage已满**

*问题*：LocalStorage空间不足，导致存档写入失败。

*处理*：
1. 写入前先检查可用空间
2. 如果空间不足，尝试删除旧版本的存档（如有）
3. 如果仍然不足，显示错误提示："存储空间不足，请清理浏览器缓存后重试"
4. 记录设计错误日志

*风险等级*：中 — 部分移动设备或隐私模式浏览器可能存在此问题

---

**边缘情况3：存档版本不兼容**

*问题*：玩家使用的是旧版本游戏创建的存档，新版本游戏无法加载。

*处理*：
1. 检测 `save_version` 的主版本号
2. 如果主版本号不同，显示提示："存档版本（X.X）与当前版本（Y.Y）不兼容，需要重新开始"
3. 询问是否删除旧存档并开始新游戏
4. 如果选择否，保持在主菜单

*风险等级*：低 — MVP阶段版本号固定为1.0.0，不存在此问题

---

**边缘情况4：存档数据损坏**

*问题*：存档JSON格式正确但内容异常（如缺少必要字段）。

*处理*：
1. 使用 `IsValidSave` 公式校验每个必需字段
2. 如果校验失败，标记存档为 CORRUPTED
3. 显示提示："存档文件损坏，是否重新开始？"
4. 如果用户确认，删除损坏存档并开始新游戏

*风险等级*：低 — LocalStorage可靠性较高，人为破坏除外

---

**边缘情况5：读取存档时发现线索来源的NPC已死亡**

*问题*：存档中某条线索的来源NPC标记为DEAD，但线索状态为DISCOVERED/UNLOCKED（说明玩家在NPC死亡前已获取）。

*处理*：
- 这种情况是**正确的**——如果NPC死亡前玩家已获取线索，线索应该保持
- 系统不需要特殊处理，正常恢复线索状态即可

*风险等级*：无 — 这是预期行为

---

**边缘情况6：同一关卡多次完成**

*问题*：玩家重新进入已完成的关卡，完成后再次撤离。

*处理*：
- `locations[location_id].completion_count++`
- `is_completed` 保持 true（已完成状态不会因为重新完成而"更完成"）
- 不影响存档设计

*风险等级*：无 — 正常增量数据

---

**边缘情况7：游戏更新后旧存档的NPC数据缺失新字段**

*问题*：游戏版本从1.0升级到1.1，新增了NPC字段（如 `last_known_position`），旧存档中该字段缺失。

*处理*：
1. 读取存档时检测缺失字段
2. 使用该字段的**默认值**填充
3. 继续加载流程
4. 记录迁移日志（`MigrationLog: field 'last_known_position' filled with default`）

*风险等级*：无 — 次版本号升级时使用此规则

---

**边缘情况8：浏览器隐私模式（LocalStorage不可用）**

*问题*：用户在隐私/无痕模式下运行游戏，LocalStorage被禁用。

*处理*：
1. 游戏启动时检测LocalStorage是否可用
2. 如果不可用，显示提示："当前浏览器不支持存档功能，请关闭隐私模式后重试"
3. 游戏可以继续运行，但无法保存/加载
4. 记录错误日志

*风险等级*：中 — 移动端Safari常见问题，需要在测试阶段覆盖

---

**边缘情况9：玩家在撤离倒计时期间受到攻击**

*问题*：玩家已进入撤离区域，倒计时开始（3秒），此时敌人发现玩家并开火。

*处理*：
- 倒计时**暂停**，直到撤离区域再次安全（敌人数量<=0）
- 这防止"一边挨打一边逃跑还能存档"的不合理情况
- 如果倒计时暂停超过10秒（`MaxExitTimerPause`），倒计时**重置为0**
- 玩家在倒计时暂停期间被击杀 → 死亡状态成立，不触发存档

*风险等级*：低 — 是预期的游戏逻辑

---

**边缘情况10：读取存档时发现线索状态为MISSING但NPC标记为ALIVE**

*问题*：理论上不应该发生——如果NPC还活着，其线索不应被标记为MISSING。

*处理*：
- 这是数据不一致，标记为错误
- 优先以NPC状态为准——如果NPC还活着，线索应该可以获取（标记为DISCOVERED）
- 记录数据不一致日志

*风险等级*：低 — 说明之前有bug导致的数据异常

### 上游依赖（存档系统依赖谁）

| 系统 | 依赖类型 | 接口说明 |
|------|---------|---------|

| **线索系统** | 硬依赖 | 接收 `ClueStateChanged` 事件，获取线索状态变更 |
| **NPC AI系统** | 硬依赖 | 接收 `NPCDeath` 事件，获取NPC死亡通知 |
| **玩家控制器** | 软依赖 | 接收 `PlaytimeUpdated` 事件，用于记录累计游玩时间 |

### 下游依赖（谁依赖存档系统）

| 系统 | 依赖类型 | 接口说明 |
|------|---------|---------|
| **关卡系统** | 硬依赖 | 提供 `LevelLoadRequest` 查询接口，恢复关卡状态 |
| **线索系统** | 硬依赖 | 提供 `ClueRestoreRequest` 查询接口，恢复线索状态 |

| **UI系统** | 软依赖 | 提供 `SaveStatusQuery` 和 `SaveCompleteNotification` |

```
│                │                        │               │

                                          └───────▶└───────────┘
```

### 关键设计约束

1. **存档系统不主动推送数据**：存档系统是被动的数据仓库，其他系统通过事件通知变更，不从存档系统"拉取"状态
2. **存档系统不处理游戏逻辑**：存档系统只负责序列化/反序列化，不处理"某关卡如何判定完成"等业务逻辑
3. **存档系统不拥有版本迁移逻辑的复杂度**：MVP阶段版本固定为1.0.0，复杂迁移逻辑在后续版本考虑

### 双向依赖检查

| 系统对 | 依赖关系 | 是否双向 | 解决方案 |
|--------|---------|---------|---------|
| 存档 ↔ 关卡 | 关卡通知存档 | 否 | 关卡系统主动推送完成事件，存档系统被动接收 |
| 存档 ↔ 线索 | 线索通知存档 | 否 | 线索系统主动推送变更事件，存档系统被动接收 |
| 存档 ↔ NPC | NPC通知存档 | 否 | NPC AI系统主动推送死亡事件，存档系统被动接收 |
| 存档 ↔ UI | 存档通知UI | 否 | 存档系统主动推送保存完成通知，UI被动接收显示 |

**不存在双向循环依赖**：存档系统是纯数据仓库，上游是事件消费者，下游是查询提供者。

## Tuning Knobs

*以下参数暴露给策划在引擎 Inspector 中直接调整，无需修改代码。*

### 存档行为参数

| 参数名 | 类型 | 默认值 | 安全范围 | 说明 |
|--------|------|--------|---------|------|
| `ExitZoneStayDuration` | Float | 3.0 | 1.0~10.0 | 撤离区域停留安全时间（秒） |
| `ExitTimerPauseOnCombat` | Boolean | true | — | 撤离倒计时是否在战斗中暂停 |
| `MaxExitTimerPause` | Float | 10.0 | 5.0~30.0 | 撤离倒计时暂停最大时长（秒），超时重置 |
| `PlaytimeUpdateInterval` | Integer | 30 | 10~60 | 游玩时间更新间隔（秒） |

### 存档存储参数

| 参数名 | 类型 | 默认值 | 安全范围 | 说明 |
|--------|------|--------|---------|------|
| `SaveVersion` | String | "1.0.0" | — | 存档格式版本 |
| `SaveKeyPrefix` | String | "severance_save" | — | LocalStorage键名前缀 |
| `SaveSlotCount` | Integer | 1 | 1~3 | 存档槽位数量（MVP固定为1） |

### 存档显示参数

| 参数名 | 类型 | 默认值 | 安全范围 | 说明 |
|--------|------|--------|---------|------|
| `SaveNotificationDuration` | Float | 1.5 | 0.5~3.0 | 存档成功提示显示时长（秒） |
| `LoadScreenShowDuration` | Float | 0.5 | 0.2~1.0 | 加载存档时黑屏显示时长（秒） |

### 容错参数

| 参数名 | 类型 | 默认值 | 安全范围 | 说明 |
|--------|------|--------|---------|------|
| `EnableEmergencySave` | Boolean | true | — | 是否启用异常中断时的临时存档 |
| `EmergencySaveThresholdSeconds` | Integer | 300 | 60~600 | 游戏运行超过此时间才允许异常存档 |

### 调参风险提示

- `ExitZoneStayDuration` 设置过低 → 玩家可能误触撤离，导致快速死亡后无存档可读
- `ExitZoneStayDuration` 设置过高 → 玩家在撤离点等待时感到无聊
- `SaveNotificationDuration` 设置过长 → 打断游戏节奏感
- `SaveNotificationDuration` 设置过短 → 玩家可能没注意到存档成功

## Acceptance Criteria

### 功能验收

| ID | 标准 | 测试方法 |
|----|------|---------|
| AC-1 | 玩家成功撤离后，LocalStorage中正确创建存档 | 完成一次撤离，读取LocalStorage验证键名和数据 |
| AC-2 | 存档数据包含所有必需字段（version/locations/clues/npcs） | 序列化前检查SaveData结构 |
| AC-3 | 读取存档后，游戏状态正确恢复（关卡解锁/完成状态） | 加载存档，进入关卡，验证解锁状态 |
| AC-4 | 读取存档后，线索状态正确恢复 | 加载存档，打开日志，验证线索状态 |
| AC-5 | 读取存档后，NPC生死状态正确恢复 | 加载存档，检查之前杀死的NPC是否保持死亡 |
| AC-6 | 撤离区域停留3秒以上才触发存档 | 人工测试：进入撤离区域，等待2.9秒后离开，确认不存档 |
| AC-7 | 撤离区域有敌人时不能存档 | 人工测试：进入撤离区域有敌人在场，确认不触发存档倒计时 |
| AC-8 | 战斗中撤离倒计时暂停 | 人工测试：撤离倒计时期间引入敌人，确认倒计时暂停 |
| AC-9 | 游玩时间正确累计 | 运行游戏30秒以上，加载存档，验证游玩时间 |

### 边缘情况验收

| ID | 标准 | 测试方法 |
|----|------|---------|
| AC-10 | LocalStorage不可用时游戏不崩溃 | 使用隐私模式浏览器测试，观察是否显示错误提示 |
| AC-11 | 存档版本不兼容时正确提示 | 修改存档的save_version为主版本不同值，验证提示 |
| AC-12 | 存档数据损坏时正确提示 | 手动破坏存档JSON，验证损坏检测 |
| AC-13 | 同一关卡多次完成只增加计数，不重复标记 | 完成关卡A，读档，再次完成关卡A，验证completion_count=2 |
| AC-14 | 撤离过程中游戏崩溃，下次启动恢复到最后有效存档 | 进入撤离区域，模拟崩溃，验证上一个存档完好 |

### 性能验收

| ID | 标准 | 测试方法 |

| AC-17 | 存档大小保持在50KB以内 | 序列化完整存档，测量JSON字符串长度 |

### 跨系统验收

| ID | 标准 | 测试方法 |
