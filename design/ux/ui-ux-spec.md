### 1.4 多警告同时触发流程

```
┌─────────────────────────────────────┐
│         Alert Layer 队列管理        │
└────────────────┬────────────────────┘
                 │
    ┌────────────┼────────────┐
    ▼            ▼            ▼
┌────────┐  ┌────────┐  ┌────────┐
│ 伤害   │  │ 状态   │  │ 任务   │
│ 指示器 │  │ 图标   │  │ 更新   │
└────┬───┘  └────┬───┘  └────┬───┘
     │           │           │
     └───────────┴───────────┘
                   │
                   ▼
          ┌─────────────────┐
          │   垂直堆叠显示   │
          │  (按类型分组)    │
          └────────┬────────┘
                   │
    ┌──────────────┼──────────────┐
    ▼              ▼              ▼
┌────────┐   ┌────────┐   ┌────────┐
│ Alert 1│   │ Alert 2│   │ Alert 3│  ◀─── 最多显示 3 个
│ (最早) │   │ (中等) │   │ (最新) │
└───┬────┘   └────────┘   └────────┘
    │                              │
    ▼                              ▼
┌────────┐                   ┌────────┐
│ 自动   │                   │ 手动   │
│ 消失   │                   │ 消失   │
│(3秒后) │                   │(点击)  │
└────────┘                   └────────┘
```

**堆叠规则：**
- 同一类型警告合并显示（如多次伤害只显示最高伤害值）
- 不同类型警告垂直排列
- 超过 3 个警告时，最早的自动消失
- 警告显示时长：3 秒（可配置）

### 3.3 手柄模式 HUD 重新定位方案 (OQ-3)

#### 设计决策

**问题**：游戏手柄是否需要特殊 HUD 布局？

**方案**：采用"可调节式重新定位"方案

**理由**：
1. 手柄模式下左手操作左摇杆，右手操作 ABXY，右手操作区域集中在屏幕右下
2. HUD 左下角（任务目标）容易被左手误触
3. 允许玩家根据习惯调整 HUD 位置

#### 手柄模式 HUD 布局调整

```
PC/鼠标模式:
┌─────────────────────────────────────────────────────────┐
│ [体力槽]                                    [弹药/武器槽] │
│                                                         │
│                              屏幕中央                    │
│                            (准星/交互提示)              │
│                                                         │
│ [任务目标]                              [线索数量/日志]  │
└─────────────────────────────────────────────────────────┘

手柄模式 (默认调整后):
┌─────────────────────────────────────────────────────────┐
│                     [体力槽]                            │
│                                                         │
│                              屏幕中央                    │
│                            (准星/交互提示)              │
│                                                         │
│                     [线索数量/日志]                     │
│                                                         │
│         [任务目标]                    [弹药/武器槽]      │
│      (左下 → 中下)                  (右上 → 右下)        │
└─────────────────────────────────────────────────────────┘

手柄模式调整规则:
- 体力槽：左上 → 正上方居中（减少左摇杆干扰）
- 武器槽：右上 → 右下（配合右手操作区）
- 任务目标：左下 → 中下（避免左手误触）
- 线索计数：右下 → 跟随武器槽调整
```

**可配置选项：**
- 无障碍设置中提供 "手柄 HUD 布局" 开关
- 关闭时使用与 KB/M 相同布局
- 开启时使用手柄优化布局

## 5. 数据接口定义

### 5.1 数据流入 (Inputs) - UI 读取的游戏数据

```
┌─────────────────────────────────────────────────────────────┐
│                    UI 系统数据输入                           │
└─────────────────────────────────────────────────────────────┘

1. 玩家控制器数据
───────────────────────────────────────────────────────────────
接口名称: PlayerState
更新频率: 变化时触发
数据结构:
  - health: int (0-100)
  - maxHealth: int (100)
  - stamina: float (0-100)
  - currentWeapon: WeaponData
  - isMoving: bool
  - isInteracting: bool

2. Sanity/Rage 系统数据
───────────────────────────────────────────────────────────────
接口名称: MentalState
更新频率: 状态变化时触发
数据结构:
  - sanity: float (0-100)
  - rage: float (0-100)
  - mentalState: enum {Stable, Anxious, Panicked, Enraged}
  - activeStatusEffects: StatusEffect[]

3. Clue & Journal 系统数据
───────────────────────────────────────────────────────────────
接口名称: JournalState
更新频率: 线索变化时触发
数据结构:
  - totalClues: int
  - discoveredClues: int
  - currentObjective: Objective
  - objectiveProgress: float

4. LOS 系统数据
───────────────────────────────────────────────────────────────
接口名称: FocusState
更新频率: 专注模式变化时触发
数据结构:
  - isFocusModeActive: bool
  - focusSourcePosition: Vector3
  - focusIntensity: float (0-1)
  - detectedSoundSources: SoundSource[]

5. World Map 系统数据
───────────────────────────────────────────────────────────────
接口名称: DiscoveryState
更新频率: 揭示事件时触发
数据结构:
  - pendingDiscovery: LocationData?
  - isDiscoveryAnimationPlaying: bool
  - discoveredLocations: LocationID[]

6. 警告/通知数据
───────────────────────────────────────────────────────────────
接口名称: AlertQueue
更新频率: 随时接收
数据结构:
  - alerts: Alert[]
  - maxVisibleAlerts: int (3)
  - defaultDuration: float (3.0s)

Alert 类型定义:
  - type: enum {Damage, Status, Mission, Warning, Danger}
  - title: string
  - message: string
  - priority: int
  - duration: float
  - canDismiss: bool
```

## 6. 开放问题与决策建议

### OQ-2: HUD 样式是否需要根据心理状态变化？

**现状**：UI 系统文档建议调整色调，但具体方案未定。

**方案选项**：

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A. 仅色调变化 | 心理异常时 HUD 边缘泛红/蓝 | 简单实现，性能好 | 变化不够明显 |
| B. 色调 + 透明度 | 异常时 HUD 边缘变色 + 轻微抖动 | 沉浸感更强 | 可能造成视觉疲劳 |
| C. 完整主题变化 | 异常时切换 HUD 样式主题 | 体验差异最大 | 开发成本高 |

**建议方案**：A（仅色调变化），在 MVP 阶段优先保证核心功能。

### OQ-3: 手柄 HUD 布局（已在本规范中解决）

**决策**：采用"可调节式重新定位"方案（详见 3.3 节）

**实现优先级**：中等（MVP 后优化）
